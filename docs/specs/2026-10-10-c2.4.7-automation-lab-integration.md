# Portfolio specification — Standalone Automation Lab page

**Status: APPROVED for local implementation only.** The user approved this spec. Stage locally; publication waits for review of the completed local build and explicit release approval.

## Goal

Integrate the accepted C2.4.7-verified, demo-only Automation Lab as a distinct, standalone portfolio page using the existing site’s design system and shared navigation/footer. Preserve existing Home, Work, Contact, and the current Lab page/AI Status Orb. Add a clear Automation Lab entry/link from the existing Lab page rather than replacing its main-nav Lab item.

## Proposed page and navigation

- New route: `automation-lab.html` in `/root/portfolio/` (filename subject to approval).
- Keep primary navigation unchanged across current pages: Home, Work, Lab, Contact.
- On `lab.html`, add an obvious featured link/card titled “Automation Lab” that opens `automation-lab.html`; keep existing Observatory and AI Status Orb content intact.
- New page uses the current portfolio shared shell: existing global stylesheet, header navigation, preloader/footer behavior, page typography/palette and responsive patterns. The demo’s visual controls/content are restyled to fit; its stage order and behavior remain as verified.
- New page navigation includes Home, Work, Lab, Contact, with a clear current-page state for Automation Lab if supported without adding a fifth primary item.

## Functional/content requirements

- Preserve all six stages: PROBLEM, DISCOVERY, WORKFLOW, AUTOMATION OPPORTUNITY, ARCHITECTURE, HANDOFF.
- Keep deterministic, illustrative recommendations and architecture; local brief generation; copy action and manual-copy fallback; Back/Continue/Restart/clear; browser-memory-only answers.
- No enquiry form, personal contact collection, backend/API configuration, `/v1/enquiries` submission, AI/model calls, analytics capturing answers, notification integration or answer persistence.
- Privacy text distinguishes browser-session answers from hosting/security provider metadata, avoids a blanket “no data is processed anywhere” claim, and explains user-controlled clipboard history.
- All architecture/recommendation copy explicitly states no live integrations, deployments or guaranteed savings.
- No new portfolio hero/orbit changes. Do not reintroduce the rejected orbit design or alter the protected AI Status Orb implementation, colors or state behavior.

## Visual and responsive direction

- Use the existing portfolio’s current design system, component patterns and typography. Do not copy unrelated reference designs or make broad redesigns.
- Adapt the Automation Lab interface to shared portfolio conventions while retaining clear stage identity and usable controls.
- Test the new route and existing Lab/Orb at desktop 1440px and mobile 390px, plus 320px and 768px; check focus, overflow and reduced-motion behavior.

## Build, privacy and release gates

- Add `automation-lab.html` to Vite MPA inputs and required root-relative asset-prefix list, if its links/assets require it. Preserve exact `/Portfolio/` case and relative navigation constraints.
- Build with both ordinary development and `GITHUB_PAGES=true`; inspect built links/assets and test the built production output locally.
- Review third-party resources/privacy metadata. Keep to existing approved resources where feasible; no new third-party request without review. Hosting metadata/log retention remains provider-dependent and must be disclosed accurately.
- Run local browser checks for all six stages, controls, keyboard focus, reduced motion, viewport widths, console/errors/network, privacy copy and absence of backend/answer egress.
- Preserve a recoverable pre-change copy and compare protected portfolio files/Orb before and after. Confirm unrelated existing routes remain in the artifact.
- Produce deployment/rollback notes and exact artifact hashes.
- Stage locally only. Do not run `scripts/publish.py` or make external requests until Sir reviews the local result and explicitly approves publication.

## Exclusions

- No Home hero replacement or new orbit composition.
- No change to Home, Work, Contact copy/layout except any unavoidable shared navigation markup requested later (current spec keeps existing primary navigation labels/order).
- No change to `lab.html` Orb internals or state colors; only a scoped Automation Lab entry is added.
- No backend, real enquiry collection, cloud service, notification, form, persistent storage, analytics or AI.
- No live portfolio publication in this implementation phase; local review only.
